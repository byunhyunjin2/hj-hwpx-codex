# hj-hwpx-codex — Codex 플러그인
# 권박사님에게 바칩니다.
Windows x64용 Codex 플러그인입니다. 필요한 문서 엔진과 실행 파일을 함께 포함했습니다.

**2.1.7:** 로컬 포트 권한 오류와 Python 문제를 구분하고 정식 승인 경로를 안내합니다. 시스템 Python 없이 포함 실행기를 사용하며, 설치 점검은 `$hjhwpx setup`으로 통합했습니다.

**채팅에 첨부한 HWP·HWPX만 로컬에서 편집합니다.** 외부에서 받은 자료도 PC에 다운로드한 뒤 채팅에 첨부하면 됩니다. 원본 위치를 다시 묻거나 다른 폴더를 찾지 않습니다. 임의 외부 URL·다른 원본·네트워크 공유에서 파일을 가져오지 않습니다. **이미 첨부한 동일 파일을 앱의 공식 첨부 기능으로 로컬 편집기에 전달하는 내부 처리는 허용됩니다.** 첨부 식별자만 전달됐다고 재첨부를 반복 요구하지 않습니다.

사용 순서: **HWP·HWPX 첨부 → 호출명령과 수정 요청 → 수정·검증 → 미리보기 → 원래 첨부 확장명으로 다운로드**. 연결 진단·같은 첨부의 로컬 전달·필요한 대체 실행은 내부에서 처리합니다. 도구 목록이나 실행 환경 정상 표시만으로 첨부가 준비됐다고 판단하지 않습니다.

2.1.5는 HTML 검토 화면만 자동으로 열고 원본 HWP/HWPX 뷰어는 열지 않습니다. 첨부 전달을 금지하던 2.1.4의 과도한 제한을 바로잡고, 식별자·원래 파일명·전달 경로를 연결하는 입력을 추가했습니다. 임시 전달 파일이 `.bin`이어도 실제 형식과 원래 첨부 이름을 검증하여 HWP는 HWP, HWPX는 HWPX로 유지합니다.

최신 배포: [**v2.1.7 hj-hwpx-codex 2.1.7**](https://github.com/byunhyunjin2/hj-hwpx-codex/releases/tag/v2.1.7). 자세한 내용은 [릴리즈 노트](RELEASE_NOTES.md)를 참고하세요.

## 설치

1. Codex의 플러그인 화면에서 `추가` → ZIP 파일 추가를 선택합니다.
2. `hj-hwpx-codex-2.1.7.zip`을 선택하고 `플러그인 추가`를 누릅니다. 압축을 풀거나 install.cmd를 실행할 필요는 없습니다.
3. 추가된 플러그인을 활성화하고 새 채팅에서 `$hjhwpx`로 호출합니다. `/skills`에서 `hjhwpx`를 선택해도 됩니다.

새 PC에서는 `$hjhwpx setup`으로 포함 실행기·패키지·로컬 포트를 점검합니다. hjhwpx에서 `setup`이라고 요청해도 같습니다. 별도 hjhwpx-setup 호출은 제공하지 않습니다. 점검은 설치나 보안 설정을 변경하지 않습니다. 전용 도구가 없으면 포함된 로컬 실행 경로로 이어갑니다.

예: `$hjhwpx 첨부한 문서의 2025를 2026으로 바꾸고 저장 전에 변경 전후를 비교해서 보여줘.`

## 기능

- HWP 5.x·HWPX 읽기와 원본 배치 미리보기
- 사진·그림을 원본 페이지 안의 위치에 표시하고, 독립 HTML 미리보기에 이미지 데이터를 포함
- 미리보기 준비 중 "변환 중" 진행 표시와 퍼센트·원형 그래프 제공
- 변경 전후 양쪽 비교·함께 스크롤·페이지 선택·작은 상단 도구 영역
- 변경은 노란색, 확인 사항은 빨간색
- 개인정보·이력서·학번 등 식별번호 보호
- 다운로드 버튼을 클릭할 때만 원래 HWP/HWPX 형식으로 검증 후 저장
- 수정안의 최신 HTML 미리보기를 Codex 내부 브라우저에서 한 번만 열어 중복 탭 방지
- 표 글자가 셀 경계를 넘지 않도록 조판 폭 안에서 표시
- 원본은 보존하고 확인 표시 색상은 저장 파일에 포함하지 않음

## 범위와 개인정보

Windows x64 및 Codex 로컬 실행 환경이 필요합니다. 개인정보 판정은 보조 수단이므로 화면을 확인한 뒤 저장하세요. 미리보기는 원본 배치에 변경안을 표시하며 실제 파일의 줄바꿈·쪽나눔은 달라질 수 있습니다. 일부 복잡한 필드·개체·표·암호·DRM 문서는 미지원이며 누락이나 불일치가 있으면 다운로드를 중단합니다. 사진 안의 글자와 OCR은 처리하지 않습니다.

문서는 컴퓨터에서만 처리하며 서버는 127.0.0.1에만 바인딩합니다. 별도 외부 서비스·API 키가 없습니다. ZIP에 실제 문서나 개인정보는 포함하지 않았습니다. 오픈소스 고지는 licenses/에 포함했습니다.

배포 ZIP에는 플러그인 파일만 들어 있습니다. GitHub 저장소에는 Codex가 업데이트를 가져올 수 있도록 마켓플레이스 목록이 함께 제공됩니다.

## 일반 ChatGPT 채팅

현재 ZIP은 로컬 실행이 필요한 Desktop only 플러그인입니다. 전용 도구가 없더라도 로컬 실행 권한이 있으면 포함 실행기로 이어갑니다. 둘 다 없는 채팅에서는 로컬 실행 연결 제한을 안내합니다. 온라인판 전환이나 외부 서버 업로드는 이 플러그인의 작업 범위에 포함되지 않습니다.

## 2.1.5 문서 배치·명단 검토 보완

긴 변경 문구는 셀 경계와 이웃 글자를 기준으로 공백 단위 줄바꿈 또는 폭 맞춤하여 표시합니다. 저장되는 HWP에도 줄바꿈이 필요하면 해당 셀의 변경 문구에 명시적으로 줄바꿈을 지정하며, 원래 제어 코드와 표 구조를 보존하는지 검증합니다. 원본 조판 위 변경 제안을 실제 한컴의 재조판 결과와 동일하다고 보증하지는 않습니다.

학번·이름 열이 있는 참석자 명단은 개인 행을 계속 보호하면서, 그 위의 행사 제목·프로그램명·교육 기간·참여 인원만 수정할 수 있습니다. 인원 수를 바꿔도 실제 명단을 지어내지 않습니다. 명시적으로 보호한 블록은 이 예외를 적용하지 않습니다.

신규 설치 모의 시험은 실제 새 PC·ChatGPT 설치에서의 도구 자동 등록과 첨부 전달 시험을 대체하지 않습니다. 수정 문자열, 원래 형식 검증 데이터, 개인정보 불변, 미리보기 배치를 각각 확인합니다.

## 설치된 PC에서 이전 안내가 반복될 때

재설치만으로 갱신 성공을 판정하지 않습니다. `hjhwpx_check_environment`의 `version`, `identity.skillSha256`, `identity.installedFilesSha256`을 비교하면 실행 서버 쪽 파일이 같은지 확인할 수 있습니다. 사용자 경로와 문서 본문은 이 식별 정보에 포함하지 않습니다. 서버 파일의 지문이 같아도 호스트가 다른 스킬이나 과거 대화 지침을 선택했는지는 별도 확인해야 합니다.

이미 첨부한 같은 문서의 호스트 공식 전달은 허용합니다. 'library.prepare_materialize 금지'라는 이전 안내가 나오면 현재 실행 지침과 불일치하는지 확인합니다. 가장 최근 파일은 현재 첨부 식별자로 대조하며, HWP 원본 뷰어의 바이너리 미지원 안내 대신 플러그인의 HTML 검토 화면을 표시합니다.

## 원본 뷰어를 열지 않는 미리보기

플러그인 작업 중 HWP/HWPX 원본 첨부를 별도 파일 뷰어로 열지 않습니다. 열기·갱신 도구가 반환하는 `previewTarget`의 HTML 검토 화면만 표시합니다. 이 화면 안의 변경 전·후 비교와 원래 확장명 다운로드는 유지합니다. 사용자가 첨부 카드를 직접 눌러 실행하는 ChatGPT 자체 뷰어는 플러그인이 비활성화하는 대상이 아닙니다.

## Python 설치 없는 Library 첨부 전달

`runtime/python-win32-x64/`에는 Python.org의 Windows x64 임베디드 배포본 3.14.8을 포함합니다. 출처와 SHA-256은 `runtime/python-runtime.json`, 라이선스는 `licenses/python.txt`에 있습니다. 설치 프로그램·pip·PATH·레지스트리 변경을 사용하지 않습니다.

Library가 제공한 공식 `library_file_transfer.py`는 수정하거나 임의로 대체하지 않습니다. 호스트가 제공한 원문을 작업 폴더에 준비한 뒤 다음 명령으로 실행합니다.

```powershell
& '<플러그인루트>/runtime/win32-x64/node.exe' '<플러그인루트>/scripts/library-transfer.cjs' --helper '<공식helper절대경로>' --transfer-json '<전달응답JSON절대경로>' --output '<같은첨부의로컬절대경로.hwp>'
```

실행기는 포함 Python만 절대경로·격리·UTF-8 모드로 실행합니다. 전달 응답은 UTF-8 BOM과 UTF-16LE도 읽습니다. 공식 helper의 표준 입력·인자·표준 출력 규약과 Library 식별정보·완료 보고는 그대로 유지하며, 성공 후에는 기존 편집 흐름으로 이어갑니다. 실제 URL·토큰을 명령 인자나 로그·답변에 공개하지 않습니다.

환경 진단의 `attachmentHelperRuntime.ready`는 포함 실행 파일·기본 모듈·무결성의 실제 검사입니다. 공식 helper 원문 제공과 호스트 완료 보고 성공까지 뜻하지 않습니다. 공식 helper가 없으면 임의 다운로드나 메타데이터 생략으로 우회하지 않습니다.

검증에서는 빈 PATH와 잘못된 Python 환경변수, 실패하는 가짜 Windows 실행 별칭을 사용했고 같은 helper 호출 규약의 원본 바이트·메타데이터·완료 응답 일치를 확인했습니다. 실제 문서 수정 시험도 통과했습니다. 현재 환경에 호스트의 공식 Library helper가 제공되지 않아 그 코드 자체의 실시간 연동은 미검증입니다.

### 로컬 실행 권한과 Python

`EACCES`/`EPERM`은 로컬 포트 권한 오류일 수 있으며 Python 미설치와 다릅니다. 진단은 `loopback.stage`로 포트 열기(listen)와 접속(connect)을 구분합니다. 실행 도구의 정식 승인 경로가 있으면 동일 명령의 승인을 요청하고 승인 후 다시 점검합니다. 거부된 권한을 우회하거나 보안 설정을 변경하지 않습니다. `ready`는 로컬 편집 준비 상태이며, Library 전달용 포함 Python은 `attachmentHelperRuntime.ready`로 별도 확인합니다. 이미 로컬에 준비된 첨부의 편집에는 Python이 필요 없습니다.

## 2.1.7 검증 범위

12개 회귀 검사 그룹, 서버·스크립트 문법, manifest 및 MCP 초기화·도구 조회를 검증했습니다. 빈 PATH·실패하는 Python 별칭·잘못된 Python 환경변수에서도 포함 Python을 실행했습니다. helper 계약 시험에서 바이트·식별자·버전·완료 콜백·UTF-16 JSON·실패 처리를 확인했습니다. 배포 ZIP을 한글·공백이 포함된 별도 경로에 풀어 포함 Node/Python 실행과 합성 HWPX 수정·검증·HTTP HTML 미리보기·원본 보존을 검사했습니다.

별도 실물 PC에서 Python을 제거한 시험, 호스트 공식 Library helper의 실시간 연동, 설치 후 실제 호출 메뉴·자연어 setup 라우팅·내부 브라우저 표시는 미검증입니다. 이번 버전에서 실제 사용자 HWP 문서를 다시 시험했다고 주장하지 않습니다. 권한 승인이 없거나 거부되는 호스트에서는 로컬 포트를 강제로 열지 않습니다. 상세 기록은 [VALIDATION.md](VALIDATION.md)와 [validation.json](validation.json)을 참고하세요.
